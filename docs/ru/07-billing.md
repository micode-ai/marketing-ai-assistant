# Система биллинга и подписок

## Обзор

Биллинг управляется через **Stripe** с тремя планами: FREE, PRO и ENTERPRISE. Новые пользователи начинают с плана FREE с 14-дневным пробным периодом.

## Планы и лимиты

| Функция | FREE | PRO | ENTERPRISE |
|---------|------|-----|------------|
| Проекты | 1 | 5 | Без ограничений |
| ИИ-генерации/месяц | 50 | 500 | Без ограничений |
| Писем/месяц | 100 | 5 000 | 50 000 |
| Участников команды | 1 | 5 | Без ограничений |
| Документов/месяц | 3 | 30 | Без ограничений |
| Интеграции | 0 | 3 | Без ограничений |
| Шаблоны чек-листов | Базовые | Все | Все + Пользовательские |
| Голос бренда | Нет | Да | Да |
| A/B тестирование | Нет | Да | Да |
| Доступ к API | Нет | Нет | Да |
| Приоритетная поддержка | Нет | Нет | Да |

## Интеграция со Stripe

### Процесс оплаты

```
1. Пользователь нажимает «Перейти на PRO» на странице биллинга

2. Фронтенд вызывает POST /api/billing/checkout
   { organizationId, plan: "PRO", successUrl, cancelUrl }

3. API получает или создаёт клиента Stripe

4. API создаёт Stripe Checkout Session
   - Price ID из STRIPE_PRICE_PRO или STRIPE_PRICE_ENTERPRISE
   - Режим: "subscription"

5. API возвращает { url: "https://checkout.stripe.com/..." }

6. Фронтенд перенаправляет пользователя на Stripe Checkout

7. Пользователь завершает оплату

8. Stripe отправляет вебхуки на POST /api/billing/webhook
```

### Портал биллинга

Пользователи могут управлять подпиской через Stripe Billing Portal:

```
1. Фронтенд вызывает POST /api/billing/portal
   { organizationId, returnUrl }

2. API создаёт сессию Stripe Billing Portal

3. Возвращает { url: "https://billing.stripe.com/..." }

4. Пользователь управляет счетами, способами оплаты, отменой
```

### Обработка вебхуков

**Эндпоинт:** `POST /api/billing/webhook` (Публичный)

| Событие | Действие |
|---------|----------|
| `customer.subscription.created` | Создание записи Subscription, обновление плана Organization |
| `customer.subscription.updated` | Обновление статуса Subscription, периода, плана |
| `customer.subscription.deleted` | Установка статуса `canceled`, обновление плана |

Подпись вебхука проверяется через `STRIPE_WEBHOOK_SECRET`.

## Статусы подписки

| Статус | Описание |
|--------|----------|
| `trialing` | Пробный период (14 дней с регистрации) |
| `active` | Оплаченная подписка активна |
| `past_due` | Платёж не прошёл, льготный период |
| `canceled` | Подписка завершена |
| `incomplete` | Ожидание начального платежа |

## Пробный период

- Длительность: 14 дней с момента регистрации
- Статус: `trialing`
- `currentPeriodEnd` = дата регистрации + 14 дней
- После пробного периода: пользователь должен обновить план или остаётся на лимитах FREE

## Переменные окружения

```env
STRIPE_SECRET_KEY="sk_test_your-stripe-secret-key"
STRIPE_WEBHOOK_SECRET="whsec_your-webhook-secret"
STRIPE_PRICE_PRO="price_your-pro-price-id"
STRIPE_PRICE_ENTERPRISE="price_your-enterprise-price-id"
```

## Поведение при отсутствии ключей

Когда ключи Stripe не настроены (режим разработки), модуль биллинга возвращает заглушки вместо вызовов Stripe API. Это позволяет приложению работать без Stripe-ключей во время разработки.

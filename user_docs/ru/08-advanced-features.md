# Расширенные функции

## SEO и ключевые слова

Отслеживайте позиции в поисковых системах и находите конкурентов для вашего проекта. Модуль SEO позволяет вести список ключевых слов, получать официальные данные о позициях из Google Search Console, вводить позиции вручную и просматривать историю ранжирования.

### Добавление ключевых слов

1. Откройте **SEO** в боковом меню проекта.
2. Нажмите **Добавить ключевое слово**.
3. Заполните поля:
   - **Ключевое слово** — фраза, по которой вы хотите ранжироваться.
   - **Целевой URL** — страница на вашем сайте, которая должна ранжироваться по этому ключевому слову. По умолчанию подставляется URL сайта проекта.
   - **Регион поиска** — какой рынок Google проверять (pl-PL, en-US, ru-RU).
   - **Интент** — Информационный / Навигационный / Коммерческий / Транзакционный. Помогает AI-сгенерированному контенту соответствовать намерению пользователя.
   - **Целевая позиция** (необязательно) — желаемая позиция, отображается как пунктирная линия на графике истории.

### Подключение Google Search Console

Подключение Search Console позволяет платформе автоматически получать официальные данные о позициях от Google. Search Console бесплатен и даёт точные данные о кликах, показах и позициях.

**Перед началом:** ваш сайт должен быть уже подтверждён в Google Search Console (через DNS-запись, HTML-файл или Google Analytics).

1. Откройте **Настройки проекта → Google Search Console**.
2. Нажмите **Подключить Google Search Console**. Откроется экран согласия Google.
3. **Если вы видите сообщение «Это приложение не проверено»:** нажмите **Дополнительные настройки**, затем **Перейти на сайт [название приложения] (небезопасно)**. Приложение используется в производственной среде и является безопасным — Google показывает это предупреждение, пока процедура проверки OAuth ещё не завершена. Статус проверки отслеживается в задаче [#70](https://github.com/your-org/marketing-ai-assistant/issues/70).
4. Предоставьте доступ **только для чтения Search Console** и завершите процесс. Вы будете перенаправлены обратно в настройки.
5. В выпадающем списке **Подтверждённое свойство Search Console** выберите ваш сайт. Список содержит все свойства, подтверждённые в вашем аккаунте Google. Приложение автоматически выбирает наилучшее совпадение для домена проекта.
6. Нажмите **Сохранить**.

После подключения в верхней части страницы **Аналитика** проекта появится блок **Позиции в Google Search** (описание ниже). На странице SEO также станет доступна кнопка **Синхронизировать из GSC**.

### Синхронизация позиций из GSC

После подключения Search Console используйте функцию синхронизации для одновременного заполнения истории позиций по всем отслеживаемым ключевым словам.

1. На странице **SEO** нажмите **Синхронизировать из Google Search Console**.
2. Платформа запрашивает данные о ранжировании за вчера из GSC, сопоставляет каждое ключевое слово по тексту запроса и целевому URL (с сопоставлением хоста), затем записывает результат в историю ключевого слова.
3. После завершения синхронизации появляется **карточка результатов** с информацией по каждому ключевому слову:
   - предыдущая позиция → новая позиция,
   - стрелки вверх/вниз, показывающие изменение,
   - метка «Нет совпадения» для ключевых слов, не найденных в данных GSC.

Карточка результатов сохраняется между перезагрузками страницы, пока вы её не закроете.

**Если совпало «0 из N»:**

Если ни одно ключевое слово не совпало, возможна одна или несколько из следующих причин:

| Причина | Что сделать |
|---------|------------|
| Сайт не проиндексирован или имеет низкую видимость | Проверьте `site:вашдомен.ru` в Google. Если появляется мало страниц, отправьте карту сайта через GSC. |
| Ключевые слова не имеют кликов/показов в GSC | Откройте GSC → Эффективность → Результаты поиска. Если ваши ключевые слова там не появляются, сайт ещё не ранжируется в топ-100 по ним. |
| Новый сайт | Новые сайты обычно начинают появляться в результатах Google через 2–6 недель. До этого используйте ручной ввод позиций (ниже). |
| Задержка данных GSC | GSC публикует данные с задержкой 2–3 дня. Сегодняшние поисковые запросы появятся через 2–3 дня. |
| Несоответствие целевого URL | Страница, которую Google фактически ранжирует, может отличаться от сохранённого целевого URL. Проверьте в GSC → Эффективность, какие URL показывает Google. |

**Ежедневная автоматическая синхронизация:** cron-задача запускается ежедневно в 03:00 UTC и автоматически обновляет историю позиций. Кнопку нужно нажимать вручную только для получения немедленного обновления.

**Частота по тарифу:** тариф FREE синхронизирует по понедельникам (топ-5 ключевых слов); PRO — ежедневно (топ-30); ENTERPRISE — ежедневно (топ-90).

### Запись позиций вручную

Используйте ручной ввод, когда GSC не подключён, когда ключевое слово слишком новое и ещё не отображается в данных GSC, или когда нужно зафиксировать позицию сегодняшнего дня до появления данных GSC.

1. В списке ключевых слов нажмите **Записать позицию** в строке нужного ключевого слова.
2. В открывшемся окне введите:
   - **Текущая позиция** — место (1–100), на котором ваш целевой URL показывается в Google по данному ключевому слову. Установите флажок **«Не в топ-100»**, если сайт не появляется в первых 100 результатах.
   - **Найденный URL** — URL, который Google показал для этого ключевого слова. По умолчанию — ваш целевой URL. Меняйте только если Google ранжирует другую страницу вашего сайта.
3. Нажмите **Сохранить позицию**.

Проверка сохраняется в историю ключевого слова с сегодняшней датой.

### Просмотр истории позиций

Нажмите **Показать историю** у любого ключевого слова, чтобы открыть его страницу с подробностями. Вы увидите:

- Линейный график позиций во времени — позиция 1 находится вверху; меньшее число означает более высокое место в результатах поиска.
- Горизонтальную пунктирную линию на уровне целевой позиции (если задана).
- Переключатель диапазонов дат: **7 дней / 30 дней / 90 дней / произвольный**.
- Таблицу последних проверок с датой, позицией и URL-ом, который Google сопоставил при каждой проверке.

### Блок «Позиции в Google Search» на странице Аналитики

При подключённом Google Search Console страница **Аналитика** проекта показывает блок **Позиции в Google Search** со следующими показателями:

| Карточка | Описание |
|----------|----------|
| Всего кликов | Сумма кликов за выбранный период |
| Всего показов | Сумма показов |
| Средний CTR | Средний коэффициент кликабельности |
| Средняя позиция | Средняя позиция (ниже = лучше; ось Y графика перевёрнута) |

Каждая карточка включает мини-график изменения метрики во времени.

Ниже карточек KPI:

- **Топ-20 запросов** — сортируемая таблица (запрос, клики, показы, CTR, позиция)
- **Топ-20 страниц** — те же столбцы, с URL вашего сайта
- **Разбивка по устройствам** — кольцевая диаграмма (desktop / mobile / tablet)
- **Топ-10 стран** — таблица трафика по странам

**Переключатель периода:** 7 дней / 28 дней / 90 дней. Данные получаются напрямую из Search Console и кешируются на срок до одного часа.

Если GSC не подключён, вместо блока отображается компактный баннер со ссылкой на настройки.

### Конкуренты

#### Добавление конкурентов вручную

На странице **SEO** перейдите на вкладку **Конкуренты**. Нажмите **Добавить конкурента**, введите название и URL сайта, сохраните.

#### Предложения конкурентов от AI

Нажмите **Предложить конкурентов с помощью AI**. Платформа отправляет контекст проекта и отслеживаемые ключевые слова AI-агенту, который предлагает до 5 реальных конкурентов с кратким обоснованием их релевантности. Просмотрите карточки предложений:

- **Одобрить** — добавляет конкурента в ваш активный список.
- **Отклонить** — отклоняет предложение (отклонённые варианты больше не предлагаются).

### Что делать, если «0 из N ключевых слов совпало»

Пройдите по этому чек-листу:

1. **Проверьте индексацию.** Введите `site:вашдомен.ru` в Google. Если появляется очень мало страниц, сайт плохо проиндексирован. Отправьте карту сайта через GSC → Карты сайта.
2. **Проверьте GSC Эффективность напрямую.** Откройте Google Search Console → Эффективность → Результаты поиска. Поищите ваше ключевое слово через фильтр. Если видны показы, синхронизация должна их вскоре получить. Если результатов нет — вы пока не ранжируетесь по этому запросу.
3. **Подождите при новых сайтах.** Совершенно новые сайты обычно начинают появляться в результатах Google через 2–6 недель после запуска.
4. **Учитывайте задержку GSC.** Данные GSC запаздывают на 2–3 дня. Синхронизация сегодня отразит позиции 2–3-дневной давности.
5. **Проверьте целевые URL.** Откройте каждое ключевое слово в приложении и убедитесь, что целевой URL совпадает с тем, что GSC указывает как ранжирующий. Исправьте несоответствия, отредактировав ключевое слово.
6. **Создавайте больше контента.** Используйте Content Studio для создания страниц и статей блога, нацеленных на ваши ключевые слова. Больше тематического контента улучшает покрытие.
7. **Исправьте техническое SEO.** Проверьте теги `noindex`, ошибки индексирования в GSC → Покрытие и отсутствие тегов canonical.

## A/B-тестирование

Проведение экспериментов для оптимизации маркетингового контента.

### Создание теста

1. Перейдите в раздел **Эксперименты** вашего проекта
2. Нажмите **Новый тест**
3. Настройте:
   - **Название** — имя теста
   - **Тип** — Тема письма, Вариант контента или Лендинг
4. Нажмите **Создать**

### Добавление вариантов

1. Откройте тест
2. Нажмите **Добавить вариант**
3. Назовите вариант (напр., «A», «B») и настройте его содержимое
4. Каждый вариант отслеживает показы и конверсии

### Проведение теста

1. Нажмите **Запустить**, чтобы начать тест
2. По мере взаимодействия пользователей фиксируются показы и конверсии по каждому варианту
3. Нажмите **Завершить** и выберите победивший вариант

## Вебхуки

Получение уведомлений при наступлении событий в вашей организации.

### Настройка вебхуков

1. Перейдите в **Настройки > Вебхуки**
2. Нажмите **Добавить вебхук**
3. Настройте:
   - **URL** — эндпоинт для получения уведомлений
   - **События** — на какие события подписаться (напр., `content.published`, `campaign.sent`, `conversion.tracked`)
   - **Секрет** — секретный ключ для верификации payload
4. Нажмите **Сохранить**

### Безопасность payload

Все payload вебхуков подписываются HMAC-SHA256 с использованием вашего секрета. Подпись отправляется в заголовке `X-Signature-256`. Верифицируйте эту подпись в вашем принимающем эндпоинте для обеспечения подлинности.

### Тестирование

Нажмите **Тест** на любом вебхуке для отправки тестового payload на ваш URL.

## Отслеживание посетителей сайта

Встройте трекинг-сниппет на ваш сайт для сбора аналитических данных.

### Получение сниппета

1. Перейдите в раздел **Аналитика** вашего проекта
2. Найдите код **Трекинг-сниппета**
3. Скопируйте JavaScript-сниппет
4. Вставьте его в HTML вашего сайта (перед `</body>`)

### Что отслеживается

| Событие | Описание |
|---------|----------|
| Просмотр страницы | Каждое посещение страницы с URL и источником перехода |
| Идентификация | Идентификация пользователя (email, имя, план) |
| Шаг воронки | Пользовательские события прохождения воронки |
| Конверсия | События конверсии (регистрация, обновление плана и т.д.) |

### Трекинг-пиксель

Для отслеживания email используйте URL трекинг-пикселя (`/t/pixel.gif`) для фиксации открытий писем без JavaScript.

## Уведомления об ошибках фоновых задач

Платформа запускает несколько фоновых заданий по расписанию:

| Задание | Что делает |
|---|---|
| Публикация в соцсетях | Публикует поставленный в очередь контент в подключённые соцаккаунты |
| Запланированный AI-агент | Запускает AI-агентов по cron-расписанию |
| Ежедневная агрегация аналитики | Суммирует дневные метрики по каждому проекту |
| Отправка email-последовательностей | Продвигает подписчиков по email-последовательностям |
| Синхронизация Google Play | Обновляет отзывы, рейтинги и установки для мобильных проектов |

Когда любое из этих заданий падает для конкретного ресурса (соцаккаунт, проект, последовательность и т.д.), платформа автоматически уведомляет по email каждого **OWNER** и **ADMIN** организации. Письмо отправляется на предпочтительном языке каждого получателя и содержит:

- Какая фоновая задача не выполнилась
- Какой ресурс был затронут (например, «Facebook: MiCode Page»)
- Текст ошибки
- Прямую ссылку на соответствующую страницу настроек

### Защита от спама

Если одна и та же ошибка повторяется (например, невалидный токен Facebook приводит к сбою публикации каждую минуту), система отправляет **не более одного письма в сутки** на уникальную сигнатуру ошибки в организации. Счётчик повторений в письме показывает, сколько раз ошибка встречалась с момента первого обнаружения. После устранения причины и успешного выполнения задачи счётчик сбрасывается.

### Смена языка уведомлений

Смените предпочтительный язык в меню в правом верхнем углу. Настройка сохраняется в вашем профиле, и все последующие уведомления будут приходить на выбранном языке.
